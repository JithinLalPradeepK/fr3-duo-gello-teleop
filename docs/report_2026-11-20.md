# Robot demo workstation - project report (status 2026-11-20)

Dual Franka FR3 teleoperation demo on one Ubuntu workstation (no Docker), ROS 2 Humble:
GELLO Duo leader arms -> two FR3 follower arms with Robotiq 2F grippers, three cameras
(ZED Mini + 2x RealSense D405), a 3-pedal foot switch and a PyQt5 GUI on two monitors.
Everything was built step by step, simulated first, and only run on the real robots with the
operator's explicit OK (physical E-stop always in hand).

## 2. The core safety problem and the start gate

**Problem:** the stock GELLO joint impedance controller fixes its motion start pose at the moment it is
activated. If GELLO data arrives later, or the GELLO is somewhere else, the robot jumps to the GELLO pose
at full stiffness.

**Solution - `gello_gate.py` (one per arm):**
- Arm controllers are launched with the impedance controller **inactive**; the GELLO publishes on a separate
  namespace (`/gello_check_<arm>`) that the controller cannot hear.
- The gate waits until the GELLO is **out of its holder and held still for 1 s**. Rule decided by the
  operator: GELLO in its holder -> the robot never moves; GELLO out of the holder -> the robot moves to the
  GELLO pose (whatever the distance) and teleop starts.
- It snapshots the GELLO pose, relays the frozen snapshot to the controller, loads a **fresh controller
  instance** (the stock one only resets its ramp in the constructor), waits until DDS has matched the
  subscription, then activates -> smooth ramp (speed factor 0.2) -> HOLD -> LIVE when the operator's GELLO
  matches the robot (0.08 rad).
- Refuses a snapshot within 0.1 rad of an FR3 joint limit; refuses if another publisher is on the
  controller's GELLO topic.
- On STOP / Ctrl-C / any fault: deactivates the controller -> **robot holds its pose**.
- Target mode (`--target-joints`) is reused for **HOME** (ramp to the saved home pose).

**Simulation first:** fake-hardware test suites on a separate ROS domain:
gate suite 91/91 single-arm + 15/15 duo checks; supervisor suite now 48/48 checks.

## 4. The demo application

**Architecture:** one `demo_supervisor` ROS 2 node owns all logic; GUI and pedal are thin clients of the
same services (`/demo/start`, `/demo/stop`, `/demo/home`, `/demo/bringup`, `/demo/shutdown`,
`/demo/recover`, gripper open/close) and the JSON status topic `/demo/status`.

- **States:** OFFLINE, STARTING_UP, IDLE, TELEOP_STARTING, TELEOP, STOPPING, HOMING, ERROR, RECOVERING,
  SHUTTING_DOWN.
- **Persistent bringup:** arm stacks, robot-state throttles (1 kHz -> 10 Hz in C++, saved ~70 % CPU),
  grippers, GELLO publisher, cameras. A camera failure is shown in the status but is never an ERROR.
- **Always both arms**; HOME only while teleop is stopped; homing and teleop can never run together
  (shared lock file).
- If the supervisor dies, the gates get SIGTERM (robots hold) and all launches are stopped.

**GUI (`demo_gui.py`, PyQt5):**
- CONTROL window (monitor 1): state banner, START / STOP / HOME, Bring up / Shut down / Error recovery,
  **Franka Desk box** (Prepare, Unlock brakes, Lock brakes, Execution, Programming, FCI on, FCI off, Park),
  status lights (Desk, Robots, FCI, GELLO, Grippers, Cameras, Pedal), per-arm details, log.
- CAMERAS window (monitor 2): the three color streams with fps.
- Closing the window asks for confirmation, then shuts the whole demo down safely.
- The GUI is not a safety device; the physical E-stop stays in use.

**Foot pedal (`demo_pedal.py`):** pedal 1 START, 2 STOP, 3 HOME; grabbed exclusively (keystrokes never
reach other windows); STOP never debounced.

**One-click start:** desktop icon "Robot Demo" -> `start_demo.sh` starts desk_agent, supervisor, pedal node
and GUI; refuses to start twice; logs to `~/robot_demo/logs/start_demo_<time>/`.

**Franka Desk integration (`franka_desk.py`, `desk_agent.py`):**
- Uses the robot's own Desk web API (system 5.10.0; endpoints taken from the robot's Desk web app).
- Password stored in the GNOME keyring, never in code or files.
- desk_agent holds the Desk control token while the demo runs (FCI is tied to the token: releasing it turns
  FCI off). All Desk buttons are refused while the arm stack is running.
- Demo starts OFFLINE: operator presses PREPARE (or Unlock / Execution / FCI on separately), then Bring up.
  Closing the demo releases control (FCI off); brakes and mode are left as they are.

**Typical operator flow:**
1. Click the Robot Demo icon (demo opens OFFLINE).
2. PREPARE robots (or Unlock brakes -> Execution mode -> FCI on).
3. Bring up -> IDLE (grippers open/close once).
4. START (pedal 1) -> take the GELLOs out of their holders, hold still 1 s -> robots move to the GELLO pose
   -> LIVE teleop.
5. STOP (pedal 2) -> robots hold. HOME (pedal 3) -> both arms to the home pose.
6. Shut down -> PARK robots (or FCI off / Programming / Lock brakes) -> close the window.

## 5. Incidents found and fixed

**Cartesian reflex during teleop (right arm, 14:56):**
- The FR3 triggered a `cartesian_reflex`. franka_hardware does not catch errors during active control, so
  the right arm process aborted and the launch stopped both arm stacks (robots stopped by the Franka).
- The GUI showed a misleading "controller could not be deactivated - use E-stop".
- Fix: the supervisor now reads the cause from the log and shows e.g. *"right: motion aborted by robot reflex
  (cartesian_reflex) - robots stopped by the Franka. Check the robots, then SHUT DOWN and BRING UP"*; no false
  alarm; Error recovery is refused in that case (it cannot work without the arm process). New sim test.
- Root-cause check: external force at rest measured (left 2.1 N, right 4.5 N). The robots already have a
  1.2 kg end effector configured in Desk, so the gripper weight is compensated - no SetLoad needed (it would
  double-count). The reflex most likely came from a fast motion or a contact. Collision thresholds unchanged.

**H4 - E-stop during teleop (passed):** E-stop -> arm process stops ("User Stop pressed!") -> ERROR with
a clear message -> release E-stop -> Shut down -> Bring up -> IDLE in 3 s (no Error recovery needed) ->
START -> LIVE -> STOP -> robots held.
**Rule:** after a reflex or E-stop: release, SHUT DOWN, BRING UP. Error recovery only for errors while the
arm stack is still running.

**Other fixes:** pedal node exits without traceback; a bouncing STOP pedal no longer sends a second stop
signal; supervisor CPU reduced from 96 % to 15 %; ROS name clashes (`handle`, `clients`) avoided; launches
made Ctrl-C safe; DDS participant limits for the simulation; desk_agent exit crash fixed.

## 6. Safety rules followed throughout

- Nothing that moves a robot or gripper was run without the operator's OK at that moment; E-stop in hand.
- Arm controllers never started together with GELLO without the start gate.
- Homing and teleop never at the same time.
- No system upgrades, no driver/kernel/bashrc changes without asking; every change to working code shown as
  a diff first, with backups in `scripts/.backup/`.
- Credentials only in the keyring.
